# AGENTS.md

## What this is
Room Planner is a client-only web app. What ships is **one self-contained HTML file** you can open off disk — that deployment model is not negotiable — but it is *built*, not hand-maintained:

```sh
npm install && npx playwright install chromium   # once
npm run dev        # Vite dev server on http://127.0.0.1:5173, HMR on save
npm run build      # -> dist/index.html, one file, everything inlined
npm test           # Vitest (unit + build pipeline), then Playwright (~45s)
npm run lint       # ESLint (correctness, import boundaries, rp/signals-memo), then npm run cycles
npm run typecheck  # tsc over the JSDoc types
```

`dist/` is **never committed**: a generated file touched by every change would conflict on every merge. It is gitignored and CI fails if it is tracked. `.github/workflows/ci.yml` runs lint, typecheck, unit, build and the browser suite on every pull request; `pages.yml` publishes `dist/` to GitHub Pages on every push to `main`. Review routing is in `.github/CODEOWNERS`.

- **`index.html`'s `<script>` is `type="module"`** (a Vite entry), so the source file does **not** run from `file://` — module scripts are fetched under CORS rules an opaque origin cannot satisfy. Open `dist/index.html` for that.
- **Runtime dependencies are small, bundle into the single file, and have a stated reason.** Everything else is a devDependency. Today there are three, one family:
  - `@preact/signals-core` (~4 kB) — the reactive core everything subscribes through (see *Committing a change*). `kernel/` imports only this one.
  - `preact` (~11 kB + ~4 kB hooks) — the UI's components (`.jsx`, automatic JSX runtime). It patches what is on screen, so a list keeps its rows, focus and scroll position across a repaint. React would be the same idea at four times the size.
  - `@preact/signals` (~5 kB) — Preact's binding to the same core (one copy in the bundle): a component that reads `signal.value` while rendering re-renders when it changes. It installs Preact option hooks when imported, which `ui-kit/component.js` (the one function every component is mounted through) does.

  Canvas rendering, geometry, model code and gesture logic are hand-written on purpose; the reasoning (no Konva/Fabric/XState/React/Redux, no Immer) is under *Decisions* in [`.claude/plans/frontend-architecture.md`](.claude/plans/frontend-architecture.md).

## How the source is laid out

**[index.html](index.html)** is a shell: `<head>`, a `<link>` to `src/app/styles/main.scss`, the page's empty places (the header, each pane's head and `<section data-sec>` slots, the canvas and its controls' slot, the Library page), two `<!-- @include -->` directives (the icon sprite and the dialog's host), and one `<script type="module">` holding the few `document`/`window` listeners that belong to no component (closing a menu, resizing, the colour-scheme change), `bindKeys()`, `edgePanTick()` and `boot()`. Everything else lives under `src/`:

```
src/kernel/            the document and its rules; no DOM
src/ui-kit/            generic UI every feature builds with
src/features/<name>/   one feature: its model, commands, components, layers, tools, keys, styles
src/app/               composition: boot, the chrome, the canvas parts list, the keyboard, the slots
```

- **`kernel/`** — state (`state.js`: `S`, `setS`; `selection.js`: the selection signals), committing a change (`tx.js`: `transact`/`preview`), revision signals (`signals.js`, plus `report()`/`notice`, how the kernel tells the person something), undo (`history.js`), persistence (`store.js`, `migrate.js`), primitives (`units`, `geometry`, `color`, `ids`), shared types (`types.d.ts`), and in `kernel/model/` the domain model several features share (`walls`, `openings`, `validity`, `floor-place`, `floor-space`, `open-state`, `item-folders`). Model code one feature owns lives in that feature. Everything here would make sense with no screen attached.
- **`ui-kit/`** — `dom.js` (`$`, for the shell's own elements), `modal.jsx` (the dialog: `openDialog`, `askText`/`askChoice`/`askTags`/`askConfirm`/`askConfirmOption`; `modal.html` is its host), `shortcuts.js` (the keyboard registry), `menu.js`, `inline-edit.js`, `dnd.js`, `tag-field.jsx`, `panels.js` (section and pane collapsing), `flash.js` + `toast.jsx`, `sprite.html` (icons), `component.js` (`mountComponent`), `parts.jsx` (`Field`, `Select`, `Check`, `RenameField`, `SecHead`, `PaneHead`, `ActButton`, `MoreButton`, `Icon`), and the control styles.
- **`features/`** — fourteen, each with an **`index.js` that is its public API** (and a header saying what the feature is): `canvas` (camera, compositor, palette, pointer dispatcher, pan tool, snapping/picking, the View section, the layers no one feature owns), `mode` (`setMode`, `activateLayout`, the mode switch, undo/redo buttons), `walls`, `openings`, `room` (Room mode, by part), `furniture`, `floors`, `measure`, `walkpaths`, `layouts` (the room tree), `library` (the Library/Marketplace page and `itemDialog`), `marketplace` (the catalogue sources), `io` (export/import), `blueprint` (the photo-to-rooms wizard).
- **`app/`** — `boot.js` (`boot()`: mounts every view, loads the project), `chrome.jsx` (header, the controls over the canvas, the panes' heads), `canvas-events.js` (the canvas element's listeners), `canvas-setup.js` (every layer and tool, in order), `shortcuts.js` (every feature's shortcuts into the registry), `slots.js` (fills the pane sections), `styles/` (`main.scss`, the cascade order; `_tokens.scss`).

**The boundaries are enforced, not described.** `rp/boundaries` in `eslint.config.js` resolves every relative import: `kernel/` imports only `kernel/` (and may not touch `document`); `ui-kit/` imports `kernel/` and `ui-kit/`; a feature imports `kernel/`, `ui-kit/`, its own files, and **other features only through their `index.js`** — never `app/`, never its own `index.js`; `app/` imports anything, features through `index.js` or, for what only the shell needs, `features/canvas/host.js`, which no feature may import. **There are no import cycles**: `npm run cycles` (the end of `npm run lint`) fails on any, so the features form a DAG with `canvas` at the bottom. When a feature needs one that needs it back, one of them is in the wrong place, or the call wants to be a signal the other side subscribes to.

### Adding things

- **A feature**: `src/features/<name>/index.js` exporting what others may use, with a header; a line in `.github/CODEOWNERS`. Its sections go in `FEATURES` in `app/slots.js`, its layers and tools in `app/canvas-setup.js`, its shortcuts in `FEATURES` in `app/shortcuts.js`, its SCSS as an `@use` in `app/styles/main.scss` where it belongs in the cascade. A whole page of its own is an empty place in `index.html` that `boot()` renders into.
- **A panel (pane section)**: a component (`.jsx`) in the owning feature that reads the signals it shows while it renders; an entry in that feature's `sections` map (`{key(el){ mountComponent(el, <MySection/>); }}`, exported from `index.js`); one `<section data-sec="key" class="for-…">` line in the pane in `index.html`; its key in the narrow `order` list in `app/styles/_narrow.scss`. Its head is a `SecHead`. Nothing else in `app/` changes.
- **A dialog**: a body component and `openDialog({title, ok, body, onOk})` (`ui-kit/modal.jsx`). A body that holds what OK reads registers the handler with `useDialogOk()`. A body is rendered once, so a box in it that its own state re-renders is controlled (`value` from state) or carries no `value` at all.
- **A layer**: a `*-layer.js` module in the feature that owns what it draws, `{id, z, scene?, deps?, draw, hitTest?}` (`/** @satisfies {import('../canvas/types.js').Layer} */`); export it from `index.js` and add it to `LAYERS` in `app/canvas-setup.js`. No existing layer changes.
- **A tool**: a `*-tool.js` module in its feature, holding its own gesture state; export it and add it to `TOOLS` in `app/canvas-setup.js` at its priority. If it is switched on and off, give it `stop()` and have its start command call `stopOtherTools(id)`; `modes` if it may not survive a mode change; `reset()` if it holds picks that belong to one room. Nothing outside the tools names a tool.
- **A shortcut**: an entry `{id, priority, keys?, modes?, run}` in the feature's `shortcuts` list (`keys.js`, exported from `index.js`), priority from `KEY_ORDER` (`ui-kit/shortcuts.js`), `modes` if it works only in some; `run` returns `false` to pass the key on. See *Keys*.

### Rules that have drawn blood

1. **Mutable shared state lives in leaf modules** that import nothing but `kernel/signals.js` — `kernel/state.js`, `kernel/selection.js`, `features/canvas/interaction-state.js`, `features/measure/measure-state.js`, `features/library/nav.js`, `features/blueprint/state.js`. A gesture's own state lives in its tool. When a big function looks unmovable, check whether what is stuck is the state it reads (move that to a leaf first) or a knot of plain calls (which has to move whole).
2. **No import cycles, and no edge that drags a top-level read into one.** `features/canvas/view.js` takes `$('cv').getContext('2d')` at module-eval time; inside a cycle it can be evaluated before what it needs, and the app dies at boot. Check a new edge with `npm run cycles`, not by eye. Break a cycle by moving the shared piece into a leaf (`ui-kit/dom.js`, `features/library/preview.js`), stating an order once in a module the parts do not import (`features/blueprint/flow.js`), or turning the back edge into a signal (`navChanged()`, the kernel's `report()`).
3. **No top-level side effects in `src/`.** Every module defines and exports; nothing registers a listener or starts work at import time (the one exception is `@preact/signals` installing its hooks, above, and `view.js`'s lazy `getContext`). `boot()`, `bindKeys()` and `edgePanTick()` are exported and called from `index.html`; a module that called them itself would run before the shell's own listeners, since imports evaluate first. A component's listeners are props on its own elements. Registration order matters only between listeners on the same element and phase: the canvas's are all in `bindCanvas()`, one per event type, and the keyboard is one listener per phase over the registry.
4. **The page markup is a textual splice.** `rp:html-includes` (`vite.config.js`) substitutes each `<!-- @include src/…/foo.html -->` before any other transform, so the shell is static markup parsed before any script runs — which is what `view.js` relies on. `test/unit-setup.js` reads `index.html` off disk and carries the same substitution: **keep the two in step**, or the jsdom shell loses its sprite or dialog host and every unit test fails while the build and the browser stay green. It asserts the ids the app needs and names the one that went missing.
5. **`test/epilogue.js` is not linted.** It imports every name Suite B reaches (`window.__rp`, `GLOBALS`) from the module that defines it. Move or rename one of those and only the instrumented build breaks — every e2e test fails with no `__rp`, lint and build green. Fix the epilogue in the same change.
6. **ESLint cannot check a name against its module.** `import {sizeLabel} from '../measure/index.js'` passes `no-undef` and the boundary rule whatever `measure` exports. Verify the module, and run the suite.
7. **Design tokens stay CSS custom properties.** Dark mode re-declares all of them under `@media (prefers-color-scheme:dark)`; a Sass `$variable` cannot cascade, so converting one deletes dark mode with every test green. `main.scss`'s `@use` order is the cascade order: put a rule where it belongs, not at the end. No `@extend`; nest at most two levels plus `&`.
8. **A move is a move.** Moving code between modules is byte-identical lines — no renames, reordering, reformatting or fixes — so `git blame` follows it. A behaviour change goes in its own commit and says so. Bugs you spot go in `BACKLOG.md`.

The header nav switches between three **places**: **Plan** (canvas + side panels), **Library** and **Marketplace** (`#paneLibrary`, which swaps in for `<main>` — `isCanvasMode()`/`applyLayoutMode()`). Inside Plan, the **Room | Furniture | Floor** switch (`ModeSeg`) sits on the canvas. `S.mode` is `'room'|'furniture'|'floor'|'inventory'|'marketplace'`; `S.planMode` remembers which canvas mode to return to. `setMode()` (`features/mode/mode.js`) is a prefs commit, so every view follows it.

**Design rules live in [DESIGN.md](DESIGN.md)** — tokens, components, wording ("item", "Library", never "thing"/"inventory" in UI copy) and a review checklist. Read it before adding UI; colours, sizes, radii and shadows come from `src/app/styles/_tokens.scss`, never literals.

## Verifying changes
`npm test` is the gate, and CI runs it plus lint and typecheck. Read [`test/README.md`](test/README.md) before touching `test/`: **test code stays under 20% of the codebase, ideally under 10%** (it measures it), and every addition needs an argument about what it catches that nothing else does.

- `npm run test:unit` (~2s) — Vitest + jsdom over modules imported straight from `src/`: units, `migrate()` goldens, `transact()`, import/export round trips, floor placement, the panels-follow-edits guard, and the build pipeline.
- `npm run test:e2e` (~40s) — builds, then Playwright + Chromium against **both** the dev server and the built file with one set of goldens: the smoke path, the blueprint geometry golden, two pointer gestures, the `file://` contract.
- **What it does NOT cover** is listed in `test/README.md` — most of what the panels and dialogs show, the canvas's pixels, most pointer interaction, the marketplace. Exercise those by hand (`npm run dev`: draw/resize a room, place furniture, undo/redo, switch units).
- `npm run typecheck` — `tsc`, no emit (`scripts/typecheck.mjs`; `tsconfig.json` explains both passes). Every module is checked at the default level; one whose first line is `// @ts-check` is held to `strict`, and `kernel/`, `ui-kit/`, every feature's `index.js`/`host.js`, every module those re-export from, and every `.jsx` must be. The script prints the modules not yet strict — the ratchet; to climb it, add the pragma and fix what it reports. Shared types are declarations: `src/kernel/types.d.ts` (the saved document, `transact()`'s scopes) and `src/features/canvas/types.d.ts` (`Layer`, `Tool`). A change to the saved shape updates `types.d.ts` alongside its `migrate()` step.
- `npm run lint` — ESLint correctness rules (`no-undef` is the one that earns its keep; unused bindings are errors), `rp/boundaries`, `rp/signals-memo` (see *Rendering*), then `npm run cycles`. No Prettier and no formatting rules, deliberately: the dense style is a decision, and reformatting would destroy `git blame`.

## Architecture
- **Units** (`kernel/units.js`): everything is stored in **millimetres**; `parseLen`/`fmtLen` convert to and from the display unit (ft+in, in, cm, mm, m). Never a second unit system — store mm, format at render time. Geometry helpers are `kernel/geometry.js`.
- **State** (`kernel/state.js`): one global `S` holds `layouts` (rooms), `inventory` (items), `folders`, `floors`, the Library's trees and UI prefs. A room is a closed polygon, `room.points = [[x,y], …]`, clockwise, mm. `S` is reassigned wholesale on load and import, always through `setS(v)` (an imported binding is read-only).
- **Persistence**: `Store` wraps `window.storage` or falls back to `localStorage`; `save()` debounces. `migrate(st)` (`kernel/migrate.js`) upgrades older saved shapes on load — **when changing the shape of `S`, add a migration step** and update `kernel/types.d.ts`. Per-room and per-item fixes go in `normLayout()`/`normItem()`, which import also runs.
- **Committing a change** (`kernel/tx.js`): every edit to saved state goes through `transact(scope, fn, opts?)`, scope `room | furn | floor | lib | prefs | project`. It runs `fn()`, records the scope's undo stack (room/furn/floor; `{history:false}` skips it), bumps the layout revision when validity or walk-path caches could change (room/furn/lib/project), `save()`s, and bumps `rev[scope]` plus `planRev` (the canvas's; `{canvas:false}` when the plan does not show the edit) — all in one `batch`, so no view runs halfway through an edit. Nested calls commit once, at the outermost. A gesture's frames use `preview(scope, fn)` (no history, no save) and its release calls `transact` once: one gesture, one undo step. **Never call `save()`, `commitRoom/Furn/Floor()`, `draw()` or a render function after an edit, and never name a panel**: every view is an effect on the signals it shows. A bare `draw()` is only for a paint needed synchronously (the Measure tool's press, whose label hit boxes come out of the draw), state that is not a signal (the camera, a gesture object mutated mid-drag), or `savePlanImage`'s light-palette capture.
- **Undo/redo**: room and furniture edits have **separate** stacks per layout (`roomHist`/`furnHist`), plus one per floor; `transact` writes them. Replaying a snapshot bumps the scope's signal like a commit; `histRev` moves with any stack (the undo/redo buttons read it).
- **Rendering**: the canvas is an effect (`mountCanvas`) that schedules one draw for the next frame whenever a commit or a signal some layer reads changes. Everything else on screen is a **Preact component**: the pane sections (e.g. `layouts/tree-section.jsx`, `furniture/items-list.jsx`, `room/sections.jsx`), the Library page (`library/page.jsx`), the dialogs, the header and the canvas controls. A component reads what it shows while it renders — `rev.room.value`, `pref('unit')`, the selection — and re-renders when that changes. Rows are keyed by model ids, listeners are props, and an element being typed in survives a repaint with its text, caret and focus. A row being renamed is a signal the row renders a `RenameField` for; a drag in flight is component state.
  - **The memoisation rule.** `@preact/signals` memoises a component that reads a signal or holds hook state: its parent's re-render reaches it only when a prop changes **by reference** — and the model is edited in place, so the same item object handed down again is not unchanged data. Such a component must read the revision signal its output depends on, or take a prop that changes whenever that data may (`epoch`, the Library page's render count). A component with neither always follows its parent, which is why `Field`, `Select` and `Check` hold no state. **`rp/signals-memo` holds this**: it fails a `.jsx` component that holds state or reads a signal (directly, or through a hook or helper declared in the same file), takes an object prop (read from its JSDoc, including a local typedef), and neither reads a revision signal (`rev.<scope>.value`, any `<name>Rev.value`) nor takes an `epoch`/`rev`/`<name>Rev` prop; and one whose props it cannot read at all. Exempt: `initial…` props (seeds for the component's own state) and a component used only as an `openDialog` body in its own file. It cannot see an imported hook or helper (other than `pref`), nor whether the revision signal read is the right one — review for those; `test/unit/panels-follow-edits.test.js` is the runtime guard.
  - **Form boxes**: a box over a model value is a `Field` (`ui-kit/parts.jsx`; `Select`, `Check`). While it has focus and has been typed in, it is the user's — a repaint leaves its text and selection alone. On commit (Enter, or leaving an edited box) it hands the text to `onCommit`, which commits through `transact()` or refuses, and then shows the model's value — so a refused edit snaps back, and Tab goes on to the next box. Dialog boxes are drafts, not `Field`s: OK reads them, and a value OK refuses stays for the user to fix under `moError()`'s message.
  - Signals (`kernel/signals.js`) are read with `.value` and written by assigning it; Set-valued ones are replaced, never mutated. The Library's browsing state (`features/library/nav.js`) is plain data; browsing calls `navChanged()`, which bumps the `navRev` signal the page reads. While a Plan mode shows, the Library page returns what it last rendered, so it neither repaints nor fetches while hidden.
- **The canvas** (`features/canvas/`): `view.js` (`cv`, `ctx`, `view`, `sx`/`sy`/`wx`/`wy`, `snapPt`) is a leaf every layer and tool imports. **Layers** draw: `draw()` (`draw.js`) paints every registered layer in `z` order, each between `ctx.save()`/`restore()`. A layer is `{id, z, scene?, deps?(), draw(ctx, view, frame), hitTest?()}`: `scene` is `'room'` (the active room) or `'floor'` (every room on the floor); `deps()` reads the signals it shows so the canvas repaints when they change; `frame` carries what several layers share (`C` = `PAL()`; `bad`/`openBad`; `fl`, `members`, `depths`, `empty`). The z order is the paint order — stage 0, floor/underlay 10–20, walk paths 30, walls 40, interior walls 50, pillars 60, openings 70, open regions 80, items 90, labels 100, guides 110, handles 120–125, measurements 130, tool overlays 140–170, readout 1000. **Tools** handle gestures: `{id, active(), onDown, onMove?, onUp?, onCancel?, onHover?, onCursor?, onLeave?, onKey?, autoPan?, cursor?, overlay?, modes?, stop?, reset?}` (`interaction.js`'s header spells each out). The active tool is the first registered one whose `active()` holds; Space hands a press to the pan tool. `onDown` returns the tool that holds the pointer until it comes up; that tool gets the moves and the release, or `onCancel` on Escape. Code outside the tools ends them by kind — `stopDrawing()`, `stopToolsFor(mode)`, `resetTools()` — never by name. Colours come from `PAL()` (`paint.js`), never literals; only stage-side colours change in dark mode.
- **Side panels**: left `#paneRoom` ("Plan") holds lists — rooms, then items (Furniture) or walls/doors/structure (Room); right `#paneStuff` ("Properties") holds the selection, then room/floor properties or stock, then View. Each section is a slot (see *Adding things*): `fillSlots()` (`app/slots.js`) fails loudly on a section nobody fills or a key with no section. `for-room`/`for-furn`/`for-floor` hide a section in other modes (`body[data-mode]`). Collapsed state is `S.secClosed` by `data-sec` key; `SecHead` folds its own section; `applyPanes()` drives `S.leftOpen`/`S.rightOpen`. Under 900px the panes become `display:contents`, the canvas is sticky and sections stack in `_narrow.scss`'s order.
- **Dialogs, menus, toasts** (`ui-kit/modal.jsx`, `menu.js`, `flash.js`): one dialog at a time, a plain `<div>` (`#modal`) in the shell's `#dialog` — never `<dialog>` or `<form>`, both blocked in sandboxed iframes the app may run in. `openDialog({title, body, ok, onOk, danger, wide, xwide, stepper, onBack, onClose, actions, focus})`; opening another replaces it (without its `onClose`); `onOk` or the body's `useDialogOk()` returning `false` keeps it open; `onClose` runs however it closes; `updateDialog()` changes the open one's OK or title. `askConfirm()` is always `danger`. The `⋯` buttons (`MoreButton`) open `openMenu(anchor, actions, title)`; anything needing more than a click opens a dialog from the menu. Rows whose single click does something use `singleClick()`/`cancelSingleClick()` so a double-click can rename. Icons are `<Icon name=…/>` over the sprite (no emoji). `flash()`/`libFlash()` stay up for `readTime(msg)`. No component looks an element up; `$(id)` is for the shell's own elements.
- **Keys** (`ui-kit/shortcuts.js`, `app/shortcuts.js`): every shortcut is `{id, priority, keys?, modes?, phase?, capture?, inFields?, run}` in its feature's list. One listener per phase on `document` (`bindKeys()`) offers a key to the entries for it from the highest priority down; `run` returning `false` passes it on. Bands (`KEY_ORDER`): a gesture's Escape, Space-to-pan, the live canvas tool's `onKey`, commands for every mode (undo/redo, `M`, `?`, Escape), a mode's own (`[`/`]` on a floor, Delete on a room part), then the selected items' (Delete, `R`, arrows). An entry is skipped outside its `modes` and, unless `inFields`, while the user types in a box. Two entries that could take the same key in the same mode may not share a priority — `bindShortcuts()` throws. The menu's Escape is the one capture-phase entry.
- **Double-click** a wall (on the plan in Room mode, or its row in the Walls list) to open `wallDialog(i)`, the same length/direction pair as the Selection panel; it relies on `setWallLen`/`setWallAngle` returning false when `tryRoomEdit` rolls the change back, and stays open over the message.
- **Reordering** (`ui-kit/dnd.js`): the room tree and the item list use HTML5 drag-and-drop. `moveBefore(arr, movedId, targetId, after)` does the splice; folders and rooms are separate arrays, so a drop reorders only against its own kind and otherwise reparents. `folderDescendant()` is the cycle guard.
- **Library** (`S.mode === 'inventory'`): the same `S.inventory` Furniture mode places, plus `item.folderId`/`item.manualTags` beside `item.tags` (the folder-inherited half — `applyTags`/`reconcileTags`) and the folder tree `S.itemFolders`. Browsing is `lib-tree.jsx` + `lib-grid.jsx`; editing an item is the same `itemDialog(id)` (`library/item-dialog.jsx`) Furniture mode uses. Its Export writes `{app, version, exported, inventory}` (the `ITEM_SCHEMA.md` shape), which the main Import reads.
- **Inventory scope**: `S.invScope` (`project | folder | room`, `INV_SCOPES`) decides which rooms `usedCount()` counts (`scopeLayouts()`). `folder` means the rooms directly in the active room's folder; a subfolder is its own pool.
- **Marketplace**: two sources, both landing on `addMarketItemToInventory()`'s collision flow. **Subscriptions** (`S.marketSubs`) are live `market.json` URLs per [MARKET_SCHEMA.md](MARKET_SCHEMA.md); `subscribeMarket()`/`reloadMarketSub()`/`removeMarketSub()`/`fetchMarketItem()` validate `app`/`version` on every manifest, shard and item; the caches are in-memory and only `{id,url,name,version,itemURL}` is saved. A subscribed item opens `renderMarketItemPreview()`, whose "Add to library" defers the add with `setTimeout` so a collision dialog can open after the preview closes. **Ad hoc listings** (`S.marketListings`/`S.marketFolders`) are the older upload/paste/link path, unrelated to the schema.
- **Ids**: an item's id is user-editable, so `idProblem()` holds it to a URL/S3-safe set — letters, digits, `! - _ . * ' ( )`, and `/` between path parts. A slash reads like an S3 key: the Library's folder tree (`rehomeItemId()` keeps an id under its folder path) and a marketplace's browse view (`marketPathChildren()`) both group by it. `retagItem()` is the only way to change an id — it rewrites `placed[].itemId` everywhere *and* in the `furnHist` snapshots, so undo cannot bring the old id back. `uniqueId(base, taken)` makes the `-2`/`-3` suffix.
- **Export / import** (`features/io/`): both pick what moves in a dialog. `exportPayload()` writes `{app, version, exported, folders, layouts, inventory}` plus `PREF_KEYS` if settings are ticked; picking a room locks on the items standing in it. `readImport()` accepts a partial file; `applyImport()` replaces or merges — an existing item id either wins ("keep mine", incoming rooms re-point to it) or the incoming one is added as `id-2`; an existing folder id **is** that folder; placements whose item resolves to nothing are dropped.
- **Blueprint import** (`features/blueprint/`): traces a photo of a floor plan into rooms on a floor. Four stages in one dialog — photo, crop, scale, review — one component module each (`step1-upload.jsx` … `step4-review.jsx`, stepper in `wizard.jsx`). None imports another: each `bpXStage(…, to)` leaves only through `to.next()`/`to.back()`, which `flow.js` hands it, so the order is written once (`bpUploadDialog` is flow.js's). `onClose` runs `bpDispose()`. **The photo never touches `S`** — `save()` serialises all of `S` into localStorage, so megabytes of base64 there would break saving permanently and silently; it lives in `bpState` (`state.js`, a leaf; written through `setBpState(v)`) until commit. Detection is a *proposal*: `bpState.proposal` is never mutated, corrections go in `bpState.edits`, and `bpRebuild()` derives the draft from scratch each time (a scale change moves every room, so it must stay idempotent over edits). `bpCleanPoly()` (`poly.js`) normalises winding, drops collinear vertices and merges sub-50mm edges **before** `polySimple()`, the only polygon gate — a weakened copy of it once made rooms permanently uneditable. The import is on no undo stack; `bpLastImport` powers "Undo this import" (`commit.js`, from the floor's menu). **Dividers** split one open region into two rooms with no wall between: a seed point and an axis stamped as one pixel of barrier into a *copy* of the mask, then the regions are re-derived by the same code — so merging is deleting a divider, and there is no polygon union. Dividers are proposed from `bpLabelBlocks()` (the positions of name labels among the components the largest-component step discards). The seam becomes its own edge carrying `wallOff`, which is what makes `floorSnapCandidates` report "Open through" and `floorEdgeDepths` draw nothing there.
- **Validation**: `validate(inst, poly)` / `insideRoom()` / `collides()` (`kernel/model/validity.js`) are the single source of truth for whether a placement is legal; reuse them.
- **Open state**: `item.open = {top,bottom,left,right}` is mm past the item's footprint in its unrotated frame. `openPoly(inst,item)` is that footprint in world space; `openConflicts()` reports what it runs into. It is deliberately **out** of `validate()` — it warns, it never makes a placement illegal.
- **Measuring**: the Measure toggle (`M`) makes the Measure tool the active one, in Room or Furniture mode. Measurements are `l.measures = [{id, a, b}]`; each end is an anchor `{k, id, part, n}` (`k`: `item|pillar|iwall|open|wall`, a wall's `id` being its index; `part`: `corner`, `side` with `n`, `whole`, or `swing` for a hinged door while swings are shown). `measureObjs()` lists what can be measured, `anchorGeom()` turns an anchor into geometry, `closestBetween()` measures. Ends are looked up on every draw, so a measurement follows what it joins; one whose end is missing is skipped (undo can bring it back) and `pruneMeasures()` drops it on load. Anything that gives things new ids must go through `remapMeasures()`. Measurements have no undo history.

## Conventions
- ES2017-ish, `"use strict"`, semicolons. JS with JSDoc types checked by `tsc`; no `.ts` sources, only `*.d.ts` declarations. Annotate what a strict module exports; prefer a precise type to a cast and a cast to `any`, and say in a comment why each cast or `any` is true. Match the surrounding style.
- **Components** are `.jsx` (Preact, automatic runtime), strict from their first line, `function` components with HTML's attribute names (`class`, `for`). A component holds its own elements: no `innerHTML`, no `$('id')`, no listeners on `document`, nothing read from the DOM at import time; lists keyed by model ids; state the model does not hold is a hook or a signal in the feature. An `id` stays only where something needs it (a `<label for>`).
- New code goes in the `src/` module or stylesheet where it belongs — **not** in `index.html`.
- `function` declarations stay `function` declarations, never `const f = () => {}`: house style, and a hoisted function survives an import cycle that a `const` read at load time would not.
- Angles: 0° points right, 90° points up (screen-plan convention); see `wallAngle`/`setWallAngle`.
- Contributor setup and review expectations are in [`CONTRIBUTING.md`](CONTRIBUTING.md) — the same ground, written for a person arriving cold.
